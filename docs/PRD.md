# Talktor — Product Requirements Document (PRD)

Version: 2025-09-04
Status: Draft
Owner: Product/Engineering

## 1. Summary
Talktor is a personal English-tutoring assistant that enables 5–10 minute practice conversations with an AI tutor and turns them into actionable learning: structured feedback across pillars, concrete corrections, personalized homework, and progress tracking over time. Sessions, feedback, and tasks are persisted so the learner can review history and measure improvement.

Primary modes include free-topic, review of previous topics/homework, situational practice (e.g., interview, ordering food), dynamic challenges based on weaknesses, and optional live suggestions during the session. The app provides a real-time transcript, session timer, token and context usage indicators, and an estimated cost. Post-session, users get a detailed summary, pillar scores, error highlights, vocabulary lists, and homework/exercises tailored to their needs.

## 2. Goals and Non‑Goals
- Goals
  - Enable natural, real-time practice (voice or text) guided by an AI tutor.
  - Persist conversations and structured feedback to enable longitudinal progress tracking.
  - Provide pillar-based scoring (pronunciation, fluency, grammar, expressions, vocabulary, comprehension).
  - Generate actionable homework (vocabulary, expressions, grammar) and written exercises.
  - Offer dashboards for progress and error trends; enable practical review via flashcards.
  - Keep the frontend decoupled from the backend via REST/WebSocket.

- Non‑Goals (initial versions)
  - Human tutor marketplace, scheduling, or payments.
  - Certification of language level or official exam preparation.
  - Multi-tenant enterprise administration and billing.

## 3. Target Users and Personas
- Beginner-to-intermediate English learners seeking structured, frequent practice.
- Busy professionals wanting short daily sessions (5–10 min) with immediate, actionable feedback.
- Self‑directed learners who value progress tracking and concrete next steps.

## 4. User Stories
- As a learner, I can start a short conversation with an AI tutor and get feedback immediately after.
- As a learner, I can choose the practice mode (free, review, situational, dynamic challenge).
- As a learner, I can see my transcript, elapsed time, tokens used, context window usage, and estimated session cost.
- As a learner, I can view a structured summary, corrected phrases, errors, and vocabulary to learn.
- As a learner, I can track pillar scores and see how they evolve over time.
- As a learner, I can receive personalized homework and practice it later (written exercises, flashcards).
- As a learner, I can review my history, notes, and see whether past errors have been corrected.

## 5. Functional Requirements
### 5.1 Agent Conversation Modes
- Topic selection / situation picker.
- Teacher mode (random topic).
- Teacher mode (previous topics/homework): incorporate past topics, lessons, and tasks.
- Situational practice (e.g., interview, ordering food, travel scenarios).
- Dynamic mode (AI selects situation).
- Dynamic weak‑point challenge (AI designs a challenge focused on user weaknesses).
- Live suggestions during conversation (toggle on/off).

### 5.2 Feedback (per session)
- Conversation summary.
- Concrete errors and corrected phrases.
- Vocabulary list extracted from the session (words/expressions to memorize).
- Pillar scores (0–10) across: pronunciation, fluency, grammar, expressions, vocabulary, comprehension.
- Homework generated based on this session and past history.
- Time spent, token usage, and cost estimate.
- Timer/limit configurable by the user (optional).
- Real‑time displays: transcript, tokens used (approx.), context window usage percentage.

### 5.3 Application Features
- Realtime conversation with RealtimeAgent (voice or text) + detailed post‑session feedback.
- Session history with summaries, feedback by category, and personal notes per session.
- Scores and categories dashboard; progress by pillar over time.
- Written exercises generated by StandardAgent based on feedback.
- Homework queues:
  - To memorize: vocabulary and expressions.
  - To study: grammar topics (practical focus).
- Frequent error tracking and trends.
- Review mode (spaced practice): generate Anki‑like flashcards from errors/homework.
- Chat mode (text), voice mode (audio).
- Gamified checklists for completed homework/review.
- Learned‑items checklist (auto‑validated if errors stop repeating in future sessions).
- Advice section based on historical performance and completed tasks.
- Configuration: personal data, interests, goals, defaults.
- Global user metrics and personal objectives.
- Comprehension/listening mode: AI speaks; user performs exercises to demonstrate understanding (summarize meaning, respond logically, or write the gist/partial transcript).

### 5.4 Pillars (definitions)
- Pronunciation: clarity, accent.
- Fluency: rhythm, pauses, continuity.
- Grammar: tenses, prepositions, structures.
- Expressions: idioms, phrasal verbs, collocations.
- Vocabulary: range and precision.
- Comprehension: follow the thread, respond meaningfully and coherently.

## 6. Success Metrics
- Session completion rate, average sessions/user/week.
- Reduction of repeated errors over rolling windows.
- Improvement in pillar scores (moving averages).
- Homework completion rate and flashcard review adherence.
- Time‑to‑first‑value (TTFV) and average session duration.
- Cost per session (tokens × price) within targets.

## 8. Architecture Overview
- General Stack (PRD baseline)
  - Backend: Python + FastAPI
  - Frontend (MVP): Streamlit or Gradio for rapid development (frontend is replaceable)
  - Database: PostgreSQL
  - AI: OpenAI APIs (GPT‑4o, Realtime, Whisper, TTS)
  - Containers: Docker + docker‑compose
  - Decoupled design: frontend↔backend via HTTP/WebSocket
- Current Implementation Note
  - The repository currently uses a web frontend (Next.js/React) decoupled via REST/WebSocket. The PRD remains frontend‑agnostic.

### Backend Layers
- API (`api/`)
  - REST and WebSocket endpoints
  - Pydantic validation for I/O
  - Calls agents and services
- Agents (`agents/`)
  - Orchestrators of conversation flows
  - RealtimeAgent: real‑time voice interaction
  - StandardAgent/TextAgent: written exercises, vocab/grammar generation
  - Agents do not persist data directly
- Services (`services/`)
  - Application logic and connectors
  - `openai_service.py`: calls OpenAI APIs (chat, STT, TTS)
  - `feedback_engine.py`: computes scores, errors, homework
  - `audio_handler.py`: voice/text conversion
  - `session_manager.py`: timers, tokens, durations
  - `persistence_service.py`: DB writes (authoritative path to DB)
- Database (`db/`)
  - PostgreSQL with SQLAlchemy models
  - `crud.py` for read/write ops; `database.py` for connection/config

### Key Decisions
- Agents never write to DB directly; they return structured outputs only.
- A dedicated service persists data (`persistence_service`).
- All OpenAI calls are encapsulated in `openai_service.py`.
- The frontend interacts only with the backend via API (swappable frontend).

## 9. Data Model (High Level)
- `users`: profile, interests, goals, preferences
- `sessions`: duration, agent_type, mode, token costs, timestamps
- `transcripts`: message content with timestamps
- `feedback`: pillar scores and structured feedback (errors, suggestions)
- `homework`: generated tasks per session (vocab/expressions, grammar, listening)
- `vocabulary_items`: words/expressions to memorize
- `grammar_items`: grammar concepts to study
- `flashcards`: spaced‑repetition cards from errors/homework
- `errors`: frequent error registry
- `notes`: personal notes per session
- `goals`: user learning objectives
- `advice`: generated advice based on history

## 10. Interfaces & Design
- Practice
  - Start session, select mode (voice/text; free/review/situational/dynamic/weak‑point), toggle live suggestions.
  - During session: transcript, tokens, context usage, timer.
  - End: summary, corrections, vocabulary, pillar scores, homework, cost/time.
- Learn
  - Homework by type/state, written exercises, flashcards, checklist, recommendations based on recent errors.
- Progress
  - Pillar evolution charts, error trends, session history with transcript/feedback/notes, links to related tasks.
- Config
  - Profile (level, interests, goals), preferences (default duration/mode, pillar priorities), export/reset.

## 11. Non‑Functional Requirements
- Performance: low latency in realtime conversation; stable WS connection.
- Reliability: graceful reconnection, backpressure handling.
- Security & Privacy: protect user data; avoid storing raw audio long‑term unless necessary; PII handling.
- Observability: structured logging, request tracing, metrics.
- Cost Control: token accounting and per‑session cost estimates; configurable budgets.
- Accessibility & Internationalization: clear UI with readable contrast; future i18n support.

## 12. Risks and Mitigations
- High latency or WS instability → buffer management, partial playback, retries.
- Token/cost overruns → display live counters, enforce limits, summarize aggressively.
- Hallucinated feedback → validation rules, score bounds, examples tied to transcript.
- User frustration with errors → transparent progress, small wins (gamification), personalized advice.

## 13. Open Questions
- Should we gate live suggestions behind a minimum level to avoid overload?
- What is the default session limit (5/10/15 minutes)?
- How to define pass/fail or mastery for automatic “corrected” tagging?
- What privacy defaults for storing transcripts/audio?

## 14. Acceptance Criteria (MVP v0.1)
- Start and end a realtime (or text) session with an AI tutor successfully.
- Persist session (metadata), transcript, and structured feedback.
- Display post‑session summary, errors, corrected phrases, vocabulary, and pillar scores.
- Provide a minimal history list with access to past session details and a notes field.
